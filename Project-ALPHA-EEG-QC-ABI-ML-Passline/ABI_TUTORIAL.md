# ABI Tutorial

This tutorial explains how to use the EEG QC Python ABI from a student
perspective. Project Alpha and Project Beta are alternatives; you only need to
submit one project.

## 1. What the ABI Does

The ABI is the boundary between the provided runner and your Python plugin.

The runner:

- reads window metadata from `sample_abi/windows_v1.csv`
- reads EEG samples from `sample_abi/eeg_samples_v1.csv`
- reads optional EOG samples from `sample_abi/eog_samples_v1.csv`
- reconstructs one `window` dictionary at a time
- calls your plugin functions
- validates your return values
- writes `sample_output/plugin_output_v1.csv`

Your plugin only needs to implement the required hook functions. It should not
rewrite the ABI input files.

## 2. Files to Know

- `abi_runtime/eeg_qc_abi.py`: Python ABI runner.
- `student_ml_plugin/plugin.py`: example ML plugin.
- `student_ml_plugin/params.json`: example runtime parameters.
- `student_ml_plugin/model_manifest.json`: model provenance and labels.
- `student_ml_plugin/feature_manifest.json`: feature names and model feature order.
- `sample_abi/`: input CSV files used for local ABI tests.
- `sample_output/plugin_output_v1.csv`: output generated by the plugin.
- `scripts/benchmark_complex.py`: one-command test package.
- `ABI_TEMPLATE.md`: exact hook names, function signatures, and return contract.

## 3. Run the Full Check

From this project folder:

```bash
python3 scripts/benchmark_complex.py
```

This is the fastest student check. It runs:

- unit tests
- sample ABI regression test
- direct plugin benchmark cases
- ABI integration benchmark cases

If this command passes, the passline package is working.

## 4. Run the ABI Runner Directly

From this project folder:

``` python3 abi_runtime/eeg_qc_abi.py --windows sample_abi/windows_v1.csv --eeg-samples sample_abi/eeg_samples_v1.csv --eog-samples sample_abi/eog_samples_v1.csv --plugin student_ml_plugin/plugin.py --out sample_output/plugin_output_v1.csv
```

This command directly tests whether your plugin can be loaded by the ABI runner
and whether its output follows the required CSV format.

To test your own plugin, replace only the `--plugin` path:

```bash
python3 abi_runtime/eeg_qc_abi.py \
  --windows sample_abi/windows_v1.csv \
  --eeg-samples sample_abi/eeg_samples_v1.csv \
  --eog-samples sample_abi/eog_samples_v1.csv \
  --plugin my_plugin/plugin.py \
  --out sample_output/plugin_output_v1.csv
```

## 5. Required Hook Functions

Your plugin module must define these exact top-level functions:

```python
def qc_decision_v1(window, params):
    ...


def feature_extractor_v1(window, params):
    ...
```

The names must match exactly. The runner looks them up by name.

## 6. What `window` Contains

The runner passes one `window` dictionary into each hook. Important fields:

- `window_id`: stable ID for this window
- `sample_rate_hz`: sampling rate
- `eeg_samples`: list of EEG channels; each channel is a list of microvolt values
- `eeg_channel_names`: EEG channel names
- `eog_samples`: optional EOG channels
- `eog_channel_names`: optional EOG channel names
- `start_sec`, `duration_sec`, `start_sample`, `end_sample`: timing metadata

Example access:

```python
def feature_extractor_v1(window, params):
    eeg_samples = window["eeg_samples"]
    channel_count = len(eeg_samples)
    return {"channel_count": float(channel_count)}
```

## 7. What `qc_decision_v1` Must Return

Return a dictionary with:

- `status`: required; one of `KEEP`, `WARN`, `REJECT`, `ABSTAIN`
- `quality_score`: optional number from `0` to `100`
- `reason_codes`: optional list of strings

Example:

```python
return {
    "status": "WARN",
    "quality_score": 72.5,
    "reason_codes": ["AMP_RANGE"],
}
```

Use `ABSTAIN` when the window cannot be evaluated, for example empty input.

## 8. What `feature_extractor_v1` Must Return

Return a dictionary of numeric feature names and values:

```python
return {
    "range_max_uv": 120.0,
    "flatline_ratio": 0.25,
    "rms_uv": 18.4,
}
```

Every value must be convertible to `float`. The ABI runner writes one output row
per feature.

## 9. Passing Parameters

The ABI runner accepts `--param key=value` arguments. They become the `params`
dictionary passed into your hook functions.

Example:

```bash
python3 abi_runtime/eeg_qc_abi.py \
  --windows sample_abi/windows_v1.csv \
  --eeg-samples sample_abi/eeg_samples_v1.csv \
  --eog-samples sample_abi/eog_samples_v1.csv \
  --plugin student_ml_plugin/plugin.py \
  --out sample_output/plugin_output_v1.csv \
  --param decision_temperature=1.0 \
  --param reason_probability_cutoff=0.5
```

Inside the plugin:

```python
temperature = float(params.get("decision_temperature", 1.0))
```

Project tests may also load values from `student_ml_plugin/params.json`.

## 10. Reading the Output

Open `sample_output/plugin_output_v1.csv`. It has these columns:

- `hook`
- `window_id`
- `status`
- `quality_score`
- `reason_codes`
- `feature_name`
- `feature_value`
- `error`

Rows with `hook == qc_decision_v1` contain the QC decision. Rows with
`hook == feature_extractor_v1` contain one numeric feature each.

Example QC row:

```csv
qc_decision_v1,w_clean,KEEP,96.091,NONE,,,
```

Example feature row:

```csv
feature_extractor_v1,w_clean,,,,range_max_uv,4.0,
```

## 11. Common Errors

`status must be one of ...`

Your `status` is not exactly one of `KEEP`, `WARN`, `REJECT`, or `ABSTAIN`.

`quality_score must be in [0, 100]`

Your score is below `0`, above `100`, or cannot be converted to a number.

`cannot load plugin module`

The `--plugin` path is wrong, or the plugin has a syntax/import error.

`missing required CSV column value`

One of the ABI input CSV files is malformed or missing a required field.

## 12. Minimum vs Higher-Score Work

The example plugin is a simplest passing-line version. Passing the passline benchmark means the code reaches the 60% baseline for the code component by loading through the ABI, returning valid output, and performing initial EEG data-quality identification on the supplied examples. For higher benchmark credit, keep the ABI contract the same, improve the implementation, and run the separate BCI IV 2a benchmark:

- add more meaningful features
- improve reason codes
- test edge cases
- document model design and limitations
- explain failure modes and false keep/false reject risks
- report BCI IV 2a sensitivity, specificity, precision, F1, and balanced accuracy, because these are the BCI benchmark grading points

Do not change the required hook names or output schema.
